# 银枢 YinShu · 交付清单

本文汇总交付内容、验证入口和已知边界。

## 一、系统概述

银枢是一个面向银行业务场景的智能体演示系统。后端使用规则 NLU、模板计划、服务端策略引擎和工具网关完成业务办理；前端提供对话、业务卡片、确认操作和决策轨迹。

当前覆盖转账、账单、理财、卡片、订阅和跨场景任务。系统不依赖外部大模型，演示数据由独立 Mock 银行核心生成。

## 四、场景与实现

| 场景 | 实现要点 | 主要代码 |
|---|---|---|
| 智能转账 | 收款人识别、同名消歧、金额与备注、AA 拆分、定时指令 | `backend/nlu/`、`backend/planner/` |
| 账单分析 | 分类汇总、环比、最大支出项、异常规则 | `backend/mock_bank/api.py` |
| 理财操作 | 产品对比、申购、赎回、适当性校验 | `wealth.*`、`backend/security/policy.py` |
| 卡片管理 | 查询、调额、冻结、挂失、二次确认 | `card.*` |
| 订阅代扣 | 周期扣费、年化成本、涨价提示、取消 | `sub.*` |
| 跨场景联动 | 预算锁定、礼物候选、下单、失败补偿 | `cross.birthday`、`COMPENSATORS` |

定时转账目前只创建待执行指令，仓库内不包含到期调度器。

## 六、工程实现

- 配置通过环境变量和 `.env` 管理；
- 请求日志包含 `request_id`，并提供 Prometheus 指标和存活/就绪探针；
- 支持可选 API Key、JWT、请求体限制和令牌桶限流；
- 会话、审计和银行数据使用 SQLite WAL；
- 会话支持进程重启后恢复待确认事务；
- 资金类步骤使用幂等键，部分步骤支持失败补偿；
- 审计使用追加哈希链，支持增量与全量校验；
- CI 包含测试、覆盖率门槛、演示剧本、评测和镜像构建。

## 七、已知边界

1. 身份系统为项目内实现，JWT 由本服务签发，尚未接入统一身份认证或网关注入身份。
2. Mock 银行只模拟限额、T+1、适当性和账户状态，不连接真实资金链路。
3. NLU 为规则引擎，长尾表达、错别字、繁简混输和拼音输入覆盖有限。
4. 多用户隔离已实现，但缺少租户配额、审计分权和完整运营能力。
5. 限流按进程计数，多 worker 部署时各进程独立。
6. 默认审计锚点保存在本地表，不能防止具有数据库写权限的主体重建整条链。
7. 数字校验覆盖回复和部分卡片文本，结构化列表不全部参与校验。
8. 定时转账没有调度器，不会自动到期执行。

## 八、审阅顺序

1. 运行 `python start.py`，按第二节的指令检查主要流程。
2. 阅读 `docs/01-架构说明.md`，了解请求如何进入计划、策略和执行阶段。
3. 阅读 `docs/02-安全设计.md`，检查权限边界、确认流程和残余风险。
4. 运行测试和评测，核对报告中的数字。
5. 阅读本文第七节和 README 的已知限制，确认系统边界。
