## 一、这是什么

**银枢 YinShu · 可信银行智能体**——面向赛题"银行 AI 智能体"的可运行系统。
一句话主张：**安全策略下沉到执行层**。即使语言模型被完全越狱，攻击者最多拿到"一笔挂起的待确认请求"，而不是资金。

- 覆盖赛题六大场景（智能转账 / 账单分析 / 理财操作 / 卡片管理 / 订阅代扣 / 跨场景联动）
- 规则+模板引擎，**确定性、可离线、指标可复现**，不依赖外部大模型
- 演示形态与生产形态同一套代码：`python start.py` / `python start.py --prod` / `docker compose up`

## 六、工程化程度

- **配置**：全部走环境变量 / `.env`，三档（dev/demo/prod），无需改代码切换。
- **可观测**：JSON 结构化日志、`x-request-id` 贯穿、Prometheus 指标、存活/就绪探针分离。
- **安全**：可选 API Key 门禁、令牌桶限流、请求体与文本上限、统一错误体不外泄堆栈。
- **数据**：SQLite WAL；会话落盘（重启不丢待确认事务）、审计哈希链、备份与校验脚本化。
- **质量**：pytest + coverage（CI 门槛 70%）、13 场剧本冒烟、评测报告自动生成、镜像构建验证。

## 七、边界与未完成项（如实告知）

1. **未对接行内统一身份认证**：仅有可选 `X-API-Key`，`user_id` 由请求体注入；生产应改由网关注入。
2. **Mock 核心系统是仿真**：限额、T+1、适当性按真实形态设计，但不接真实资金链路。
3. **NLU 为规则引擎**：确定性优先，长尾表达覆盖有限；已留 LLM 适配位（只影响话术，不影响决策）。
4. **单租户演示数据**：固定客户"张明"，无多用户隔离。
5. **限流为进程内计数**：多 worker 下各自独立，生产建议换 Redis。
6. **审计可被高权限者重写**：建议把链尾哈希外发 WORM 实现外部锚定。
