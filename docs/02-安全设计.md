# 银枢 YinShu · 安全设计与自评

> 适用版本：1.1.x
>
> 适用对象：银行业务智能体演示系统
>
> 组织方式：资产、威胁、控制、残余风险、验证证据

## 一、结论摘要

| 项目 | 结论 |
|---|---|
| 权限判断位置 | 服务端策略引擎决定 `AUTO / CONFIRM / HANDOFF / DENY`，前端不能提交档位 |
| 高风险操作 | `CONFIRM` 档在用户确认后执行；`HANDOFF` 和 `DENY` 不进入自动执行 |
| 状态变化 | 确认阶段重新预览、重算指纹并重新决策，降低预览与执行之间的状态漂移风险 |
| 重复提交 | 资金类工具要求幂等键；确认事务 ID 参与幂等种子 |
| 审计 | 追加哈希链，默认增量校验，支持全量校验和可选外部锚定 |
| 数字来源 | 回复和部分卡片文本执行数字校验，结构化列表不全部覆盖 |
| 未覆盖范围 | 真实银行认证、KMS/HSM、生产级外部锚定和独立身份服务 |

## 二、资产与信任边界

| 资产 | 内容 | 保护目标 |
|---|---|---|
| A1 资金 | 账户余额、转账、申购、赎回、锁资金 | 完整性、授权、不可抵赖 |
| A2 客户信息 | 姓名、卡号、手机号、账户信息 | 机密性、最小化采集 |
| A3 决策依据 | 风险分、规则命中、计划和确认记录 | 完整性、可追溯 |
| A4 待确认事务 | 计划、预览结果、决策和会话状态 | 完整性、防重放、防超时执行 |
| A5 渠道凭据 | API Key、JWT 密钥、外部锚定凭据 | 机密性，不进入普通日志 |

信任边界：

```text
用户/渠道
  │ 不可信文本
  ▼
编排层
  │ 白名单工具调用
  ▼
工具网关
  │ 身份头 + 幂等键
  ▼
Mock 银行核心

安全横切：注入检测、策略引擎、数字校验、审计、脱敏
```

用户输入和工具返回的备注、商户名、产品名等字段按数据处理，不进入指令位置。直接访问 Mock 银行核心的请求不经过智能体工具网关，其安全边界由部署网络和核心系统自身负责。

## 三、威胁与控制

| # | 威胁 | 场景 | 控制 | 残余风险 |
|---|---|---|---|---|
| T1 | 直接提示注入 | 要求忽略规则、冒充身份或绕过确认 | 15 条规则、不可见字符和同形字检测；强信号直接拦截 | 新话术仍可能漏判，依赖策略层和执行层约束 |
| T2 | 间接提示注入 | 备注、商户名或工具返回内容夹带指令 | 工具输出按数据处理，并扫描不可信字段 | 富文本渲染和新增字段需要持续检查 |
| T3 | 越权代办 | 文本自称行长或要求操作他人账户 | 身份来自 JWT/请求上下文，资源按主体校验，超限转人工 | 默认 JWT 由本服务签发，未接统一认证 |
| T4 | 参数伪造 | 不存在的收款人、异常金额或越界工具参数 | 工具白名单、schema 校验、服务端归属与限额校验 | 依赖工具注册表和下游校验完整性 |
| T5 | 重放与重复执行 | 网络重试导致重复转账、申购或锁资金 | 幂等表、唯一索引、确认事务 ID 参与幂等种子 | 跨系统调用仍需统一幂等约定 |
| T6 | 数字幻觉 | 回复中的金额与工具结果不一致 | 模板与事实集比对，覆盖回复和部分卡片文本 | 结构化列表不全部进入校验；规则路径本身不生成未知数字 |
| T7 | 审计篡改 | 修改历史审计记录 | 追加哈希链、检查点、可选外部锚点 | 有数据库写权限的主体可重建整条链，除非启用外部 WORM |
| T8 | 会话劫持 | 获取 `session_id` 后替用户确认 | 会话绑定主体和设备，跨主体请求被拒绝，确认有效期受限 | 渠道侧会话安全仍需单独保障 |
| T9 | 不可逆操作误执行 | 未指定卡片时直接挂失，或选错候选 | 目标不明确时返回候选；不可逆操作二次确认 | 候选匹配规则仍需要业务校验 |
| T10 | 资源耗尽 | 高频请求、超大请求体或大量来源地址 | 令牌桶限流、64KB 请求体上限、500 字文本上限、限流桶回收 | 多 worker 下计数独立 |
| T11 | 敏感信息泄漏 | 日志或审计中出现完整卡号、手机号 | 审计写入前执行 PII 脱敏，日志避免输出凭据和完整敏感字段 | 新增日志字段需要继续遵守脱敏规则 |
| T12 | 旁路访问 | 绕过智能体直接访问 Mock 核心 | 生产部署应将核心系统置于内网并启用服务鉴权 | 仓库内 Mock 核心默认面向本机演示 |

## 四、控制措施

### 4.1 输入检测

- 15 条规则覆盖指令覆盖、身份冒充、凭据索取、绕过确认等模式；
- 对零宽字符、双向控制字符、同形字和全角字符执行归一化或检测；
- 强信号直接拒绝，可疑信号交给策略引擎提升风险档位；
- 输入规则只作为一层控制，资金操作仍由策略引擎和工具网关约束。

### 4.2 权限分级

硬规则优先于评分：

```text
黑名单收款人            → DENY
理财适当性不符          → DENY
单笔超过 5 万（转账类） → HANDOFF
跨境收款                → HANDOFF
```

评分：

```text
基础动作风险 + 金额/收款人/设备/时段/频率等特征
0–29   AUTO
30–69  CONFIRM
70–100 HANDOFF
```

策略配置位于 `config/policy.json`，部分金额和频率判断条件仍在代码中。修改硬规则或新增动作时，需要同步策略配置和测试。

### 4.3 数字来源校验

1. 回复由模板和事实集生成；
2. 校验前先剥离日期和时间，避免日期片段被当作独立数字；
3. 回复中的数字需要出现在事实集中；
4. 确认卡的 `title`、`note`、`rows`、`lines` 参与校验；
5. 违规时回退到模板文本并记录审计信息。

当前校验范围不包括所有结构化卡片字段。账单分类、理财明细、订阅列表等仍直接使用工具返回值，因此这些数据的安全性依赖工具输出和上游核心系统。

### 4.4 确认与会话

| 项目 | 当前实现 |
|---|---|
| 确认有效期 | 默认 300 秒，可通过 `YINSHU_CONFIRM_TTL` 调整 |
| 二次确认 | 挂失等不可逆操作需要再次确认 |
| 状态机 | `IDLE / CLARIFY / CHOOSE / AWAIT_CONFIRM` |
| 持久化 | SQLite WAL，进程重启后可以恢复待确认事务 |
| 并发控制 | 条件更新版本号，阻止同一事务重复执行 |
| 取消 | 删除待确认事务，不执行资金步骤 |

### 4.5 审计与补偿

当前审计记录使用 v2 哈希公式，内容覆盖前一条哈希、时间、trace、主体、设备、动作、参数哈希和结果。旧记录按 `chain_ver` 校验。

- 默认从最近检查点增量校验；
- `/api/audit/verify?full=true` 执行全量校验；
- `/api/audit/{trace_id}` 返回该请求的审计记录；
- 默认锚点为本地表，可配置 `YINSHU_ANCHOR_URL`；
- 只有声明补偿器并配置 `on_fail=compensate` 的步骤支持逆序补偿。

### 4.6 系统防护

| 项目 | 默认值 | 说明 |
|---|---|---|
| 接入鉴权 | demo 关闭，prod 建议开启 | 支持 API Key 和 JWT |
| 限流 | demo 为 0，prod 默认 120 rpm | 令牌桶，多 worker 下进程内计数 |
| 请求体上限 | 64 KB | 超限返回 413 |
| 文本上限 | 500 字 | Pydantic 校验 |
| 错误响应 | 生产不返回堆栈 | 统一错误体带 `request_id` |
| CORS | demo 宽松，生产需配置白名单 | `YINSHU_CORS` |

## 六、数据与隐私

- 演示数据由 `backend/mock_bank/seed.py` 生成，不包含真实客户信息。
- `backend/security/pii.py` 在审计写入前执行文本脱敏，并为原文生成 HMAC 摘要。
- 日志记录请求标识、路径、状态和耗时，避免输出凭据和完整敏感字段。
- 会话保存业务计划、预览结果和确认状态，不保存支付凭据。
- 生产环境应使用独立审计实例、加密卷或数据库加密，并将锚点写入 WORM 存储或存证服务。

## 七、残余风险

| # | 风险 | 影响 | 建议 |
|---|---|---|---|
| R1 | 默认身份实现由本服务签发 JWT | 中 | 接入 OIDC、mTLS 或网关注入身份 |
| R2 | 会话数据库未加密 | 中 | 使用 SQLCipher、加密卷或托管数据库 |
| R3 | 本地审计锚点可被高权限主体重建 | 中 | 启用外部 WORM、时间戳或存证服务 |
| R4 | 多 worker 下限流独立 | 低 | 使用 Redis 等共享令牌桶 |
| R5 | 规则 NLU 覆盖长尾表达有限 | 中 | 使用脱敏语料扩充测试集，保留规则或小模型回退 |
| R6 | Mock 核心行为与真实系统存在差异 | 中 | 接入前重新验证超时、限额、幂等和错误码 |
| R7 | 自建评测集存在同源偏差 | 中 | 引入独立标注集和规则作者隔离 |
| R8 | 数字校验未覆盖全部卡片字段 | 低 | 扩展事实集抽取与卡片字段校验 |
