# 银枢 YinShu · 运维手册

> 面向部署和运维人员。以下命令默认在仓库根目录执行；涉及 shell 语法时会分别标注 Bash 和 PowerShell。

## 一、运行形态

| 形态 | 命令 | 适用场景 |
|---|---|---|
| 本地演示 | `python start.py` | 单进程、自动生成数据、自动打开浏览器 |
| 生产模式 | `python start.py --prod` | 多 worker、JSON 日志、启用限流 |
| 容器 | `docker compose up -d --build` | 后端、Mock 核心、数据卷和健康检查 |

首次运行：

```bash
pip install -r requirements.txt
```

开发环境另需：

```bash
pip install -r requirements-dev.txt
```

数据默认保存在 `data/`，可用 `YINSHU_DATA_DIR` 指向挂载卷。

## 二、启动与停止

Bash：

```bash
python start.py
python start.py --reset
YINSHU_ENV=prod YINSHU_WORKERS=4 YINSHU_API_KEYS=<key1,key2> python start.py --prod
```

PowerShell：

```powershell
$env:YINSHU_ENV = "prod"
$env:YINSHU_WORKERS = "4"
$env:YINSHU_API_KEYS = "<key1,key2>"
python start.py --prod
```

容器：

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f app
docker compose down
```

`start.py` 会管理后端子进程，按 `Ctrl+C` 时发送终止信号。容器环境使用 `docker compose down` 停止服务，数据卷默认保留。

## 三、健康检查

```bash
curl -s http://127.0.0.1:8000/healthz
curl -s http://127.0.0.1:8000/readyz
curl -s http://127.0.0.1:8000/api/health
curl -s http://127.0.0.1:8000/metrics
curl -s http://127.0.0.1:8000/api/audit/verify
```

预期：

- `/healthz` 返回 200；
- `/readyz` 在 Mock 核心可用时返回 200，否则返回 503；
- `/api/health` 返回银行连通、审计统计、策略阈值、版本和环境；
- `/metrics` 返回 Prometheus 文本；
- 审计校验返回 `{ok,total,tail}`，具体数值随运行状态变化。

建议监控：

| 指标 | 建议 |
|---|---|
| `/readyz` 连续失败 | 1 分钟内失败 3 次告警 |
| `yinshu_errors_total{code="INTERNAL_ERROR"}` | 大于 0 时排查 |
| `yinshu_http_request_seconds` P95 | 根据部署环境设置阈值 |
| `yinshu_rate_limited_total` 突增 | 检查限流阈值、攻击流量或共享出口 IP |
| 审计链 `ok=false` | 立即停止写入并排查 |

## 四、日志

- `YINSHU_LOG_JSON=1` 输出 JSON 日志，生产模式默认开启；
- 关键字段包括 `request_id`、`method`、`path`、`status`、耗时和来源地址；
- 排查单次请求时，先从响应头获取 `x-request-id`，再检索日志；
- 审计记录可通过 `/api/audit/{trace_id}` 查询；
- 日志和审计字段的脱敏由 `backend/security/pii.py` 处理。新增日志字段时需确认不会写入完整卡号、手机号或凭据。

Docker 日志检索示例：

```bash
docker compose logs app | grep '"request_id": "84afe3c6"'
```

## 五、重启恢复演练

确认事务默认有效期为 5 分钟。演练时应在有效期内完成重启和确认。

1. 创建待确认事务：

```bash
python - <<'PY'
import httpx
c = httpx.Client(base_url="http://127.0.0.1:8000", trust_env=False)
r = c.post("/api/chat", json={"text": "给我妈转8000"}).json()
print(r["session_id"], r["state"])
open("sid.txt", "w").write(r["session_id"])
PY
```

2. 停止后端：

```text
Windows: taskkill /PID <pid> /F
Linux:   kill -9 <pid>
Docker:  docker compose kill app
```

3. 重启后端：

```bash
docker compose up -d app
```

4. 使用同一会话确认：

```bash
python - <<'PY'
import httpx
sid = open("sid.txt").read().strip()
c = httpx.Client(base_url="http://127.0.0.1:8000", trust_env=False)
r = c.post("/api/chat", json={"session_id": sid, "text": "确认"}).json()
print(r["state"], r["reply"])
PY
```

预期返回回执；如果事务已过期，会返回重新发起提示。

## 六、数据与备份

| 文件 | 内容 | 备份策略 |
|---|---|---|
| `data/bank.db` | 演示银行数据 | 不要求备份，可通过种子脚本重建 |
| `data/app.db` | 审计哈希链、锚点和幂等记录 | 建议备份，只追加写入 |
| `data/session.db` | 会话和待确认事务 | 可选，丢失只影响进行中的会话 |

Bash 在线备份：

```bash
mkdir -p backup
sqlite3 data/app.db ".backup 'backup/app-$(date +%F).db'"
```

容器内备份：

```bash
docker compose exec app python -c "import sqlite3; sqlite3.connect('/app/data/app.db').execute(\"VACUUM INTO '/app/data/backup.db'\")"
```

恢复审计数据库后执行：

```bash
curl -s http://127.0.0.1:8000/api/audit/verify?full=true
```

默认锚点保存在本地表。启用 `YINSHU_ANCHOR_URL` 后，校验还会比较外部锚点。

## 七、常见故障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `bank=False app=True` | 8010 端口被占用或 Mock 核心未启动 | 检查 `http://127.0.0.1:8010/v1/health`，或修改 `YINSHU_BANK_PORT` |
| 前端连接被拒绝 | 后端未监听 | 检查 `/healthz` 和启动日志 |
| 本机请求被代理接管 | 系统代理影响回环地址 | 设置 `NO_PROXY=127.0.0.1,localhost`；客户端已默认 `trust_env=False` |
| 写入明显变慢 | 审计库未启用 WAL | 检查 `PRAGMA journal_mode` 是否返回 `wal` |
| 大量 429 | 限流阈值过低或共享出口 IP | 调整 `YINSHU_RATE_LIMIT_RPM` |
| 接口返回 401 | 已配置 API Key 但请求未携带 | 添加 `X-API-Key`，或检查 JWT 配置 |
| 确认提示已超时 | 超过 `YINSHU_CONFIRM_TTL` | 重新发起业务或调整有效期 |
| 演示数据被前序操作修改 | 转账、取消订阅等改变了状态 | 执行 `python -m backend.mock_bank.seed --reset` |
| pytest 报告临时目录权限错误 | `%TEMP%` 受限 | 确认仓库内 `.tmp/` 可写，当前配置使用 `--basetemp=.tmp/pytest` |
| 多 worker 下限流不准确 | 限流为进程内计数 | 接入共享限流服务，或单进程部署 |

## 八、性能观察

性能与机器、Python 版本、数据库状态和下游服务有关。仓库不附带固定性能承诺。建议在目标环境使用相同数据量测试：

```bash
python -m pytest --cov=backend --cov-report=term-missing
python -m tests.run_eval
```

可重点观察：

- 审计写入是否启用 WAL；
- 工具网关连接池复用是否生效；
- SQLite 数据文件是否位于本地磁盘；
- 多 worker 下会话和审计并发是否出现锁等待。

## 九、发布与回滚

1. 运行测试、演示剧本和评测；
2. 构建带版本号的镜像，例如 `yinshu:1.1.0`；
3. 更新 `docker-compose.yml` 中的镜像标签并部署；
4. 回滚时切换到上一版本镜像标签，再执行 `docker compose up -d`；
5. 恢复数据库前先备份审计库，恢复后执行全量校验；
6. 会话表结构变更应提供迁移脚本，避免直接覆盖数据卷。

版本号需要与 `pyproject.toml`、`backend/core/config.py` 和镜像标签保持一致。
