# 安全与工程质量评审记录

> 日期：2026-10-27
>
> 对象：银枢 v1.0.0 至 v1.1.0 的加固过程
>
> 状态：历史评审记录，当前能力边界以 README 和 `docs/02-安全设计.md` 为准。

## 一、评审范围

本轮评审覆盖审计链、确认流程、幂等、身份、策略配置、限流顺序、工具返回内容处理、资金补偿和候选选择。评审以代码路径、并发行为和可复现测试为依据。

共记录 6 项高优先级问题和若干中优先级问题。当前仓库已包含对应修复与回归用例；历史数字不再作为当前测试结果使用。

## 二、高优先级问题

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | 审计链依赖进程内锁 | 多 worker 同时追加时可能产生多个链头，校验失败 | 改为 thread-local 连接和 `BEGIN IMMEDIATE`，增加 busy_timeout，并使用检查点分块校验 |
| 2 | 确认阶段复用旧预览 | 余额、收款人状态或频率变化后，可能按旧决策执行 | 确认时重新预览、重算参数指纹、重新决策，并通过版本条件更新抢占执行权 |
| 3 | 幂等键随 trace 漂移 | 客户端重试可能生成新 key，造成重复执行 | 改为按主体、设备、请求体和待确认事务派生，或使用客户端显式提供的关键字段 |
| 4 | 会话 ID 可作为确认凭证 | 获取待确认会话后可尝试触发执行 | 会话绑定主体和设备，跨主体请求返回 403 |
| 5 | 策略配置未完全生效 | 修改 `policy.json` 后部分硬规则仍由代码分支处理 | 改为谓词表解释执行，配置错误在加载时失败 |
| 6 | 限流位于鉴权内层 | 未通过鉴权的请求不消耗限流额度 | 调整中间件顺序，使限流先于鉴权执行 |

## 三、中优先级问题

| # | 问题 | 修复 |
|---|---|---|
| 7 | 工具返回的备注、商户名等字段未进入间接注入检测 | 对不可信字段执行扫描，命中时提升风险档位 |
| 8 | 礼物下单失败后锁定的预算未释放 | 增加失败补偿，释放对应锁资金记录 |
| 9 | “好的，不过改成 600”可能被当作确认原金额 | 识别金额变化，按新金额重新执行 |
| 10 | 否定句可能被当作转账意图 | 增加否定表达识别 |
| 11 | 同名同关系收款人默认选择第一条 | 只要存在并列候选就返回选择卡 |
| 12 | 卡片文本未参与数字校验 | 将 `title`、`note`、`rows`、`lines` 纳入校验范围 |

## 四、验证中发现的问题

- 在全新克隆环境中，pytest 的临时目录父目录不存在，导致会话存储用例在初始化阶段失败。已由 `tests/conftest.py` 创建 `.tmp/` 并保留仓库内 basetemp。
- 权限引擎包含凌晨时段加分，导致同一输入在白天和凌晨得到不同档位。测试和评测已使用固定时钟，演示环境可通过 `YINSHU_FIXED_HOUR` 固定小时。
- 网关 GET 请求未透传用户身份头，导致读请求退化为默认用户。已统一 GET 和写请求的身份头处理。
- 幂等键可能包含非 ASCII 字符。已增加 ASCII 降级，避免请求头编码异常。

## 五、当前仍存在的限制

1. JWT 由本服务签发，尚未接入统一身份认证。
2. 多用户隔离已实现，但缺少租户运营、配额和审计分权。
3. 默认审计锚点保存在本地表，无法防止高权限主体重建整条链。
4. 限流计数保存在进程内，多 worker 下不共享。
5. 规则 NLU 对长尾表达、错别字和繁简混输覆盖有限。
6. 数字校验未覆盖全部结构化卡片字段。
7. 定时转账仅创建指令，没有到期调度器。
